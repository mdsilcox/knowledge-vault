# Build 1 retro (2026-10-04)

Walking skeleton: checker, sync hook, hubs, installer, real install, live checks. Two Sonnet lanes (vault-core, installer) plus orchestrator contracts and live work.

## What went well
- Contracts first (skill text, CLAUDE.md section, templates, stubs, red tests) let both lanes finish green in one pass; vault-core needed no return round, installer one.
- The installer's merge-don't-overwrite design held on the real machine: settings.json kept every key and hook, CLAUDE.md kept its bytes and CRLF endings, backups written, rerun was a no-op.
- The live loop worked end to end: a note written in one session was found by meaning from another project and read on the iPhone.

## Defects found live (not caught by the suite)
1. **Mixed line endings in a generated hub.** Git on this PC (`core.autocrlf=true`) checked `templates/project.md` out with CRLF; the hub built from it was half CRLF, half LF (basic-memory writes LF), and exact-text edits stopped matching. Fix: normalize the template to LF when creating a hub, and a `.gitattributes` with `* text=auto eol=lf` in the tool repo.
2. **Edit commit messages showed a permalink** (`vault/projects/knowledge-vault`). Fix: use the last path segment.
3. **Hubs and the README outranked real notes in hybrid search.** A hub repeats every note title in its list and the README describes the whole vault, so in a small vault their keyword matches beat the real note. Vector-only ranked the note first. Fix: the skill searches with `note_types` limited to the five content types, and the README has `type: readme`.

## Environment gotchas
- **Microsoft Store Python can't start uv-managed Pythons.** The system `python` here is the Store build; processes it launches can't see `%APPDATA%\uv\python\...`, so `step_checks.py` failed with `No Python at '"C:\Users\...\uv\python\...'`. Fix: run such helper scripts with the project's `.venv/Scripts/python.exe`.
- Python 3.12's `Path.read_text` has no `newline` parameter (3.13+); read bytes and decode to keep CRLF intact.
- basic-memory adds frontmatter to every Markdown file it indexes, including a root README.

## Change next time
- Run one live write through the real tools before the gate review, not after: all three defects were invisible to unit tests.
- Generated files should never inherit line endings from the checkout: normalize at write time.
- Give every non-note file in the vault its own `type` so searches can exclude it.
